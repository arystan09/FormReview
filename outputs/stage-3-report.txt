FormReview — stage 3 of exactly 10

Outcome
Implemented a keyless synthetic extraction-to-review preview. A reviewer can run
replay on a supported synthetic canonical source, inspect all five fields with
server-derived evidence and flags, and explicitly create an initial draft bound
to that run/text version. Later extractions never replace the draft. No approval,
draft editing, live provider, paid capability or regex baseline was implemented.
The stage-3 keyless walkthrough is demonstrated; full MVP remains due after stage 4.

Actual behavior and important files
- extraction/schemas.py: strict Pydantic 2 contract, all five required keys;
  present/missing/ambiguous require 1/0/2 distinct candidates. Rejects extra fields,
  confidence/offset fields, type coercions, duplicate candidates, empty values,
  invalid Unicode/NUL and overlong quotes/values. JSON duplicate keys are rejected.
- extraction/evidence.py: finds exact quotes across canonical pages, requires unique
  occurrence on the claimed page, checks exact value membership, derives half-open
  Unicode code-point offsets. Repeated/missing/wrong-page quotes have no fabricated
  highlight. Value mismatch/repetition is explicitly flagged. Matching is not truth.
- extraction/normalization.py: preserves source strings for name, registration,
  email and country; only full explicit NetN/Ndays patterns normalize to 0–365.
  Other terms remain unresolved. No inferred jurisdiction or identifier verification.
- extraction/config.py and providers.py: persist full prompt_text, model, settings,
  JSON schema, schema/normalizer/evidence versions and content hash. Provider input
  is built from stored config plus canonical source/version metadata, with integrity
  checks. No labels, reviewer/gold decisions, filenames or membership authority enter
  the request. Config mutations change config/request hashes. The default prompt
  is used to create config records, not substituted over stored request contents.
- extraction/replay.py and fixtures/synthetic_v1.json: authored, visibly synthetic
  responses keyed by real canonical hashes of the 12 development sources. Unknown
  source hashes fail explicitly. Replay accepts the actual config payload; changing
  a prompt changes hashes, not the authored response. No model or network is used.
- extraction/models.py/migrations: immutable ExtractionConfig, ExtractionRun and
  FieldCandidate; explicit replay mode, config/source/request/response hashes and
  version references. PostgreSQL triggers prevent output/config changes and validate
  reference hashes. Invalid outputs are recorded as failed validation with no candidates.
- reviews/models.py/migrations: initial ReviewDraft, unique per document, explicit
  run/text version and revision. DB checks enforce matching source/run/document.
  Creation uses Document→Draft locks and expected_revision; conflicting revisions
  or replacement runs receive 409. No silent overwrite or review decisions.
- extraction/api.py/templates: owned JSON and source/fields preview with escaped
  exact highlights and manual-review flags. Viewer role is read-only; writes require
  reviewer membership and CSRF. Updated source screen links to replay/previews.
- Updated settings/URLs, Docker packaging, CI/Makefile type-check scope, README,
  AGENTS.md, pyproject.toml and uv.lock. Pydantic 2.14.4 is frozen; no provider SDK added.
- New unit/evidence/contract and PostgreSQL replay tests; synthetic fixture generator
  reads source bytes/hashes, never development truth labels.

Run the feature
Prerequisites: Python 3.12, uv 0.13.9, PostgreSQL 18 with UTF-8. Docker/Compose v2
is needed for the normal DB/container commands; Docker remains absent on this host.
From the repository root:
  uv sync --frozen --all-groups
  docker compose up -d db
  uv run python manage.py migrate
  uv run python manage.py bootstrap_workspace --username reviewer --workspace "Local demo"
  uv run python manage.py runserver 127.0.0.1:8000
In another terminal:
  uv run python manage.py process_jobs
Use an existing stage-2 reviewer instead of bootstrapping if one already exists.
Bootstrap prompts for a password; never put real credentials in shell arguments.

 datasets/dev/01_complete.txt, and wait for worker parsing. Open the source page,

  supplier_name: correct anchored Supplier: Alder Parts quote;

04_ambiguous_email.txt has two real source candidates; 08_two_pages.pdf deliberately

Interfaces
POST /documents/{id}/extractions: form mode=replay, reviewer session and CSRF.
GET /api/v1/extractions/{id}: owned output, candidates, offsets, flags and references.
GET /extractions/{id}: source/field preview.
POST /documents/{id}/drafts: run_id and expected_revision=0 for initial creation.
GET /drafts/{id}: owned draft preview. Existing draft idempotency requires matching
run and current revision; no replacement/edit/approval endpoint exists.

Mock/live distinction
Replay is authored synthetic output, not live model inference. Malformed-output and
payload-propagation tests use test doubles around ReplayProvider. Evidence matching,
canonical parsing, database constraints/concurrency and browser inspection are real.
There is no live-model validation, model accuracy measurement or independently
reviewed gold claim. Development labels remain separate and provisional.

Known limits
Schema status validated means structural validation, not correctness or semantic
truth. Conservative duplicate-quote checks span all source pages. Draft preview is
read-only after initial binding; editing, overrides, reasons and human approval
belong to stage 4. Only bundled source hashes support replay. If canonical parser
output changes, fixtures require explicit regeneration; there is no fallback guess.
Inherited Docker/resource/remote-CI gates remain open. No stage 4 work was done.
Temporary browser server and scratch database were stopped after verification.
