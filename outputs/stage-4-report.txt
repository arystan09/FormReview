Actual changes
- extraction/providers/openai.py: OpenAI Responses structured JSON adapter using
  the actual immutable prompt/model/settings/schema. No tools or agent loop.
  Fixed official endpoint; no proxy environment or redirects; store=false;
  max 3,000 output tokens, 30-second transport and outer deadline, retries=0.
  Refusal, truncation, invalid output, rate limit and uncertain outcomes are explicit.
  SDK/transport parent and child debug loggers are silenced to avoid content leaks.
- extraction/config.py, models.py, live.py, live_api.py and management/commands/
  configure_live.py: allowlisted pinned model/config/key fingerprint, dated price
  estimate, explicit signed reviewer confirmation, a finite durable lifetime count,
  a global active slot and minimum 60 seconds between admissions. Paid mode is
  disabled unless the local owner enables it. No request is made by configuration.
- LiveAttempt is an additional durable pre-request record, separate from immutable
  completed ExtractionRun. Its submitted marker commits before network activity.
  Two workers cannot dispatch it twice. Unknown outcomes retain the slot. Owner
  reconciliation requires an explicit worker-stopped/provider-finished attestation;
  it neither retries nor refunds an attempt. No automatic replenishment.
- reviews/services.py, approval.py, api.py and models.py: strict five decisions,
  expected_revision, source candidate validation, reasons/provenance for manual
  values, optional-missing reasons, required name/email and final value validation.
  Document→Draft locks plus role recheck protect save/approve. A single transaction
  creates ApprovedRecord, ApprovalReceipt and ReviewEvent and closes the draft.
  Same approval request reuses its receipt; stale/mismatched requests conflict.
  Immutable snapshot includes source/run/config hashes and manual provenance.
- PostgreSQL migrations enforce immutable records/events/receipts, source bindings,
  monotonic allowance consumption and non-retryable live attempt transitions.
  Guard migrations are deliberately irreversible; back up before migrating.
- Review/edit/confirmation/record/export templates and local JavaScript complete
  the workflow. Replay, live and manual-only modes remain visibly distinct.
  Sources link to existing drafts/records and owned live attempts. Public-demo
  domain writes and live admission are blocked. No publication occurred.
- process_jobs handles parsing and confirmed live attempts using the same app.
  Compose supplies the optional provider key only to worker, never web.
- Dependencies frozen in uv.lock include OpenAI 2.54.0, Playwright 1.65.2 and
  pytest-playwright 0.10.0. CI adds Chromium and offline browser checks without keys.
  README, AGENTS.md, safe environment example and ignore rules were updated.
- New tests cover SDK transport/errors/debug logging, real PostgreSQL races and
  approval rollback, permissions/CSRF, and browser review/approval/export.
  scripts/demo_smoke.py runs the real replay/manual browser workflows.

Run locally
Prerequisites: Python 3.12, uv 0.13.9, PostgreSQL 18 with UTF-8 and a dedicated
local database. Docker/Compose v2 is the documented database/container route.
For tests the database user needs CREATEDB; use a disposable server, never production.
Chromium requires the Playwright installation below (Linux may need --with-deps).
Run these commands in the FormReview project directory:

  uv sync --frozen --all-groups
  cp .env.example .env
  docker compose up -d db
  uv run python manage.py migrate
  uv run python manage.py bootstrap_workspace --username reviewer --workspace "Local demo"
  uv run python manage.py runserver 127.0.0.1:8000

In another terminal:
  uv run python manage.py process_jobs

Compose reads .env. Local Python does not implicitly load it: export POSTGRES_HOST,
POSTGRES_PORT, POSTGRES_DB, POSTGRES_USER and POSTGRES_PASSWORD if using non-default
local settings. Bootstrap prompts privately for a new password.

Open http://127.0.0.1:8000/accounts/login, select the workspace and upload
 datasets/dev/01_complete.txt. Refresh after parsing; run synthetic replay and
create its draft. Accept supplier_name, country and payment_terms_days candidates;
mark registration_id missing with a reason. Manually correct contact_email to
alder@example.test with reason and source provenance. Save all five decisions,
inspect confirmation, check the human-approval checkbox, approve and export JSON.
Alternatively upload a source and create a manual-only draft before any other draft.
All five manual values require reasons and provenance. No key is needed for either.

Known limits and review notes
No live schema/model compatibility proof until authorized smoke. Stored wire schema
omits unsupported conditional allOf; the server still enforces strict five-field
cardinality. Provider schema success is not truth. Price estimates use a conservative
byte/token approximation plus maximum output tokens, not an invoice or hard dollar
cap; owner pricing must be checked against official sources within seven UTC days.
Only one initial draft per document; new extraction never replaces it. All five
valid decisions must be saved together. Manual fallback requires a parsed source.
Unknown submitted attempts deliberately block further admission until reconciliation.
No OCR, regex baseline, deployment or later-stage features were added.
